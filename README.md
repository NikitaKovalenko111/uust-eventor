# 🎓 UUST Eventor
> Система онлайн-регистрации и организации студенческих мероприятий

[![Status](https://img.shields.io/badge/status-MVP%20in%20progress-blue)]()
[![Stack](https://img.shields.io/badge/stack-Go%20%7C%20React%20Native%20%7C%20PostgreSQL-orange)]()
[![DevOps](https://img.shields.io/badge/devops-Docker%20Compose-green)]()

Единая мобильная платформа-каталог для студенческого сообщества. Позволяет самостоятельно создавать, находить и посещать мероприятия, общаться в комментариях, добавлять друзей и получать персональные рекомендации. Система устраняет фрагментацию информации об университетских событиях, предоставляя ролевой доступ, пре-модерацию контента и умный поиск.

## 🛠 Технологический стек

| Слой | Технология | Обоснование |
|------|------------|-------------|
| **Frontend** | Expo, React Native, TypeScript | Кроссплатформенность, строгая типизация, быстрый девелопмент |

| **Backend** | Go + Fiber | Высокая производительность, минимальное потребление памяти, Clean Architecture |
| **Database** | PostgreSQL 15 | ACID, встроенный FTS (`tsvector`), нативные индексы, триггеры `updated_at` |
| **Storage** | MinIO (S3-compatible) | Изоляция медиафайлов, лёгкая замена на облачное хранилище без изменения кода |
| **DevOps** | Docker, Docker Compose | One-command deploy, healthchecks, изоляция окружений |

## 📁 Структура репозитория
Проект содержит клиентскую часть на TypeScript (React/React Native) и сервер на Go.

## Структура репозитория

- `client/` — фронтенд-приложение (TypeScript, React/React Native). Содержит UI-компоненты, страницы, навигацию и Redux + Sagas.
- `server/` — бэкенд на Go. Содержит домены `auth`, `event`, `user`, платформенные пакеты и HTTP-транспорт.
- `docker-compose.yaml` — конфигурация для локального запуска сервисов.

---

## 🏗 Архитектура

Проект построен по принципам **Clean Architecture + Modular Monolith**:
- `transport/http/` → маршрутизация, парсинг DTO, контроллеры
- `services/usecase/` → бизнес-логика, проверка прав, валидация статусов
- `storage/repositories/` → SQL-запросы, маппинг `rows.Scan()`
- `domain/models/` → строгие структуры сущностей (`User`, `Event`, `Comment`, `Attendee`)
- `platform/` → кросс-доменные утилиты (конфиг, логирование, middleware, HTTP-хелперы, MinIO-клиент)
- `app.go` → Composition Root (явное внедрение зависимостей)

Такая структура позволяет писать unit-тесты для `usecase` независимо от БД и HTTP, а при росте нагрузки выносить любой домен в микросервис без рефакторинга ядра.

## 🚀 Быстрый старт

1. Запустить все сервисы через Docker Compose (рекомендуемый способ):

```bash
docker-compose up --build
```

2. Локально (фронтенд):

```bash
cd client
npm install
npm run start
```

3. Локально (сервер):

```bash
cd server
go build ./...
./cmd/main.exe # или запустить бинарник для вашей ОС
```

## 📚 Документация API
После запуска сервера откройте Swagger UI:
```
http://localhost:8080/swagger/index.html
```
Авторизация в Swagger
1. Выполните POST /api/v1/auth/login с вашими учётными данными
2. Скопируйте access_token из ответа
3. Нажмите 🔐 в правом верхнем углу Swagger UI
4. Введите: Bearer <ваш_token>
5. Нажмите Authorize
